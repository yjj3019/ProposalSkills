# 문체와 문구 규칙

## 기본 문체

- 답이나 성과를 먼저 말하고 근거·상세를 이어 쓴다.
- 문장과 문단마다 핵심 생각을 하나로 둔다.
- 필요한 경우 주체·행위·산출물·기한·수용 조건을 명시한다.
- 능동형 동사와 구체 명사를 사용한다.
- 필요한 약어는 처음에 설명하고 이후 승인된 용어 하나로 통일한다.
- 모호한 효과를 수행 원리와 측정 가능한 결과로 바꾼다.
- 사실·확약·가정·권고를 구분한다.
- 발주처 용어를 따르되 불명확한 원문을 사실처럼 복제하지 않는다.

## 영문 작성 예시

다음 표의 문장은 영어 제안서 작성용 예시다. 실제 근거와 승인된 값으로 각 항목을 채우며,
예시 문장을 현재 고객의 사실이나 확약으로 그대로 사용하지 않는다.

| 목적 | 영문 문장 예시 |
|---|---|
| 고객 문제 | `[Current condition] causes [business/operational impact]. The buyer needs [target state] by [date/condition].` |
| 핵심 제안 | `We propose [scope and method] to achieve [measurable outcome] while controlling [material risk].` |
| 요구 응답 | `Comply. [Actor] will [action] using [method]. Evidence/acceptance: [artifact or criterion].` |
| 부분 준수 | `Partially comply. [covered scope]. [gap] requires [decision/change] by [owner/date].` |
| 차별화 | `Unlike [defined alternative], this approach [verifiable difference], which enables [buyer outcome].` |
| 역량 | `[Buyer need] is addressed by [mechanism], producing [operating effect] within [scope/boundary]. Evidence: [approved source or acceptance test].` |
| 비교 | `Against [defined criteria and baseline], option [label] differs in [verified dimension]. For this buyer, that means [implication], subject to [condition].` |
| 복원력 | `For [failure event and protected scope], the design targets [approved recovery objective] through [protection/orchestration], verified by [test and evidence]. Residual risk: [boundary].` |
| 사례 관련성 | `In an approved comparable context, [intervention] produced [verified outcome]. It is relevant here because [shared condition], but differs in [material limit].` |
| 일정 | `[Phase] runs from [start] to [finish]. Exit requires [deliverable and approval].` |
| 위험 | `If [risk] occurs, [impact] follows. [Owner] will reduce likelihood/impact by [control], monitored through [indicator].` |
| 가정 | `This schedule/cost assumes [condition]. If it changes, [impact and change process] apply.` |
| 근거 미비 | `[unverified] [claim] — confirm [source, version, date, and scope] before approval.` |

## 영문 과장 표현과 수정 원칙

근거 없는 best, unique, perfect, innovative, revolutionary, 100%, zero downtime,
fully automated, complete coverage, risk-free, guaranteed, industry-leading, seamless,
significant savings 등의 표현은 거부한다. 정확한 기능·경계·근거·기대효과로 바꾼다.
발주처 원문은 출처를 밝혀 인용할 수 있지만 제안사 자신의 사실 주장으로 반복하지 않는다.

| 영문 부적절 표현 예시 | 안전한 처리 |
|---|---|
| `100% secure` | 제거하고 승인된 통제·범위·잔여 위험을 설명한다 |
| `zero downtime` | 승인된 중단 목표·측정 경계·제외 조건·시험 근거를 명시한다 |
| `guaranteed savings` | 기준선·측정 방법·효과 귀속 기간·승인 조건을 명시한다 |
| `industry-leading` / `unique` | 최신 비교 조사와 비교 대상이 정의돼 있지 않으면 제거한다 |
| `fully compliant` | 정확한 요구·근거·예외·승인 상태를 나열한다 |

## 제안 요약 검토 질문

1. 고객이 어떤 결정을 내려야 하는가?
2. 현재 어떤 문제와 영향이 중요한가?
3. 무엇을 제안하며 왜 믿을 수 있는가?
4. 어떤 측정 가능한 성과와 위험이 중요한가?
5. 다음 단계와 필요한 결정은 무엇인가?
