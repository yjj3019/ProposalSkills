# 한국 공공 제안 — 공식 근거 레이어

이 문서는 게이트 규칙이 **왜** 존재하는지를 공식 규범에 연결한다. 규범 조문을 옮기지 않는다.
구체 값은 언제나 해당 사업의 공고 원문에서 추출한다. 업종별 질문·입증 항목은
[sectors/public.md](sectors/public.md), 스키마는 [audit-schema.md](audit-schema.md)에 있다.

## 1. 권위 순위 (충돌 시 위가 이긴다)

1. 수정공고(변경공고)
2. 본 RFP(제안요청서·과업지시서)
3. 공식 Q&A 회신(명확화 — 공고를 대체하지 않는 한)
4. 평가표(배점·평가방법)
5. 지정 제출양식
6. 승인된 사내자료
7. 아래 현행 공식 규범·가이드
8. 일반 방법론(`../create-best-proposal/references/external-method-boundaries.md`)

공식 규범은 발주기관이 공고를 **만드는 기준**이다. 제안사가 공고를 해석하는 근거로 쓸 수는
있지만, 공고에 적힌 값을 규범으로 덮어쓰지 않는다. 규범과 공고가 달라 보이면 질의로 확인하고
`[NEEDS INPUT: 발주처 질의 — 항목]`으로 남긴다.

국가법령정보센터(행정규칙)에서 현행본을 다시 확인하고, 확인일을 갱신한다.

주의:

- 계약예규 소관 부처가 재편된 뒤 발령된 개정본이 있을 수 있다. 위 계약예규 번호는 확인
  시점에 검색된 최신 게재본이며, 인용 전 재확인 대상이다.
- 공공 SW 제안요청서 작성 가이드, 기술성 평가기준 적용 가이드 같은 **해설서·가이드**는
  강제 규범이 아니다. 발간 연도가 오래된 판은 용어 이해를 위한 역사 자료로만 쓴다.
- 지자체·공공기관은 자체 계약 규정을 추가로 둔다. 공고가 인용한 규정을 우선한다.

## 4. 상수로 두지 않는 값

아래 값은 사업마다 다르다. 스킬·게이트·예제 어디에도 국가 공통 기본값으로 넣지 않는다.

- 기술:가격 배점 비율, 협상적격 비율, 부문별 과락
- 본문·요약본 분량 한도(쪽·장), 파일 용량 한도
- 용지(A4/A3), 방향(세로/가로), 화면 비율
- 최소 글자 크기, 줄 간격
- 익명본 요구, PDF 변환 요구, 바인더·인쇄 부수
- 평가 부문 개수, 발표(PT) 유무와 시간

공고에 값이 없으면 추정하지 않는다. 비워 두고 질의 대상으로 기록한다. 85% 협상적격 기준의
해석(배점한도 대비 비율)은 [sectors/public.md](sectors/public.md) «기계가 검사하는 것»을 따른다.

## 5. 이 문서의 한계

- 조문 해석을 제공하지 않는다. 계약상 판단은 발주처 질의 회신 또는 법무 검토로 확정한다.
- 확인일 이후의 개정을 알지 못한다. 확인일이 6개월을 넘기면 §2 표를 재확인한다.
