# 공공조달·나라장터 대응 (대한민국)

한국 공공·준공공 IT 입찰에서 반복되는 제약이다. 일반 규칙의 우선순위는
`bid-and-submission.md`이며, 본 문서는 공공 특화 체크만 보강한다.

## 1. 참여·자격

- 사업자 등록, 소프트웨어사업자(해당 시), 실적·업력·자본금 등 **계량 자격**은
  참여 판단의 하드게이트다(미달=불참, 증빙만 미확보=조건부).
- 조달청·나라장터·교육·지자체 포털별 **제출 매체·부수·마감 시각·시간대**를 원문에 따라
  정규화한다. "영업일" 해석이 애매하면 보수적으로 두고 가정 표기.
- 공동수급·하도급 실적 인정은 공고가 명시한 범위에서만 치유 수단으로 검토한다.

## 2. 평가·입찰 구조

- 기술·가격 배분, 협상/적격/최저가 여부를 조기에 표로 옮긴다.
- 정량 배점(실적 건수·금액 밴드)은 증빙 가능한 값만 넣고, 추정에는
  `[INFERRED—확인 필요]`를 붙인다.
- 발표평가가 있으면 발표 요약본은 본제안 축소 복사가 아니라 질문 순 재구성
  (`proposal-structure.md` 발표 요약본 절).

## 3. 제안서·서식

- 지정 목차·서식·쪽수·폰트·여백이 있으면 **내부 표준보다 지정 서식 우선**.
- 표지 기재(공고번호·사업명·업체명·법인인감 등) 누락은 형식 실격 위험이 크다.
- 가격제안서 분리 시 기술 제안서·노트·파일명·첨부에서 가격·원가 노출 0건
  (`package_inspect.py` 가격힌트 + 사람 확인).

## 4. 증빙·확약

- 실적증명, 인증서, 제조사 확약, 확약서·서약 목록을 RFP 제출 서류 목록과 1:1 대조.
- 선정 후 제출 서류도 blocking input으로 올려 마감 전 확보 계획을 적는다.

## 5. 보안·개인정보

- 공공 클라우드·망분리·보안적합성·개인정보 영향은 해당 공고·가이드라인 원문을 따른다.
- 추측으로 "국가 인증 완료"를 단정하지 않는다 — 인증 범위·대상 제품·유효기간을 병기.

## 6. 이 스킬과의 연결

- 참여 판단·수정공고·제출 규정: `../bid-and-submission.md`
- 클라우드 MSP 수행 패턴: `cloud-msp.md`
- 완료·제출 준비: `../acceptance-criteria.md`, SKILL.md 완료 선언 조건
