# 클라우드·MSP 제안 패턴

IaaS/PaaS 전환, 관리형 서비스(MSP), FinOps·보안 운영이 핵심인 사업용 보강 가이드다.
본문 뼈대는 `content-patterns.md`와 함께 쓴다.

## 1. 범위 경계 (반드시 표로)

| 구분 | 포함할 것 | 빼지 말고 명시할 것 |
|---|---|---|
| 랜딩존 | 계정/구독 구조, 네트워크 허브, 로깅·보안 가드레일 | 앱 리팩터 범위 제외 여부 |
| 마이그레이션 | Wave·Go/No-Go·롤백 (content-patterns §4) | 앱 코드 수정 책임 주체 |
| MSP 운영 | 모니터링·장애·변경·백업·패치 | 고객 책임(IAM 최종 승인, 데이터 분류) |
| FinOps | 예산 알림, 태그 정책, 월간 최적화 보고 | 요금 할인 약정 대행 권한 |
| 보안 | CSPM/CWPP, 취약점, 인시던트 협력 | 인증·감사 책임(공유책임모델) |

## 2. 공유책임모델 페이지

- CSP / MSP / 고객 책임을 RACI로 그린다. "공동"만 쓰지 말고 A(승인)는 1곳.
- 데이터 상주·암호화 키(고객관리키 여부)·관리자 접근 경로를 도식화한다.

## 3. SLA·운영

- 가용성·응답·복구 목표를 **측정 정의·제외 사유(계획 작업)·크레딧**과 함께 쓴다.
- 이원 SLA(상시 원격 + 정기 방문)가 있으면 content-patterns의 이원 SLA 규칙을 따른다.
- 변경관리: 표준/긴급 변경, 승인 창구, 롤백 소유자.

## 4. 인력·공수 (MSP)

- 역할(클라우드 아키텍트, 운영, 보안, FinOps)별 **M/M·상주/온콜**을 한 원장으로.
- 멀티클라우드면 자격(예: 공식 프로페셔널 인증)은 **개인 증빙 ID**와 연결하고
  회사 자격과 혼동하지 않는다.
- 야간·휴일 온콜 에스컬레이션 트리를 1페이지에.

## 5. 보안·규정

- 공공·금융이면 `public-procurement-kr.md` + 금융 보안 완료증거 표(content-patterns).
- SBOM·취약점·이미지 서명 등은 "도구 도입"이 아니라 **완료증거·잔여위험 승인**까지.

## 6. 금지·주의

- 특정 CSP 마케팅 문구 복붙, 미확인 리전/SLA 수치 단정.
- 고객 계정 실명·구독 ID·내부 호스트명을 예제·스크린샷에 포함 금지.
