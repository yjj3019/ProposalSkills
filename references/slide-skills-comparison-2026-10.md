# 외부 장표 스킬 5종 정밀 비교와 ProposalSkills 반영 결정

분석일: 2026-10-02. 공개 저장소의 확인 시점 HEAD를 고정해 README, SKILL, 참조 규칙,
제작·추출·검증 스크립트, 테스트 및 라이선스를 읽었다. 전체 Git 이력, 실제 외부 이미지 API,
각 호스트의 모델 실행, 웹 발표 런타임을 모두 검증한 분석은 아니다. README의 설명과
코드에서 확인한 동작을 구분한다. 외부 파일을 ProposalSkills에 복제하지 않았다.

## 2. 저장소별 구조·품질 판단

### consulting-pptx-skill

`references/slide-rules.md`, `content-review-prompt.md`, 컴포넌트 HTML, `check_deck.py`,
`check_layout.mjs`로 내용·형태·기계 검사·의미 검토가 나뉜다. 강점은 주장부터 쓰는 장표,
관계에 맞춘 패턴, 제목과 본문의 항목 수 대조, 전 장 스토리 검토다. 내용 검토에서 페이지와
실제 문제를 연결하는 방식이 제안서에도 유용하다.

렌더 검사는 브라우저에서 좌표를 측정하지만 지정한 선택자·배치에 한정된다. 스크립트의
단계 수 검사는 연번의 최대값을 사용하므로 중간 번호 누락까지 확인하는 완전한 시퀀스 검사는
아니다. 채움률·줄바꿈 추정도 실제 글꼴 렌더 품질과 동일하지 않다. 규칙에는 제목을 주장으로
만드는 지침과 명사형 제목 검사도 공존하므로 한국어 제안서의 기존 제목+리드문 구조로 해석했다.

**반영:** 내용 관계→기존 type 선택표, 스토리와 도식 결론·항목 수 대조, 근거가 있는 지적 형식.
**보류:** HTML 파이프라인 이식, 일본어 금지어 복제, 새 검토 에이전트의 의무화,
결함을 정해진 개수만큼 요구하거나 모델 자기 점수로 품질을 승인하는 방식.

### pptx-design-styles

`SKILL.md`는 용도별 추천표를 제공하고 `references/styles.md`에 30종 스타일의 색·폰트·
배치·시그니처를 모은다. 디자인 토큰과 선택 기준의 일관성이 강점이다. 실제 생성은 별도
PPTX 스킬에 의존하므로 스타일 지침만 설치해도 생성·검증 기능이 생기는 것은 아니다.

일부 해외 폰트, 다크 배경, 네온, 모든 페이지의 장식 요소 요구는 한국어 글꼴 가용성과 공공
제출 규격에 맞지 않을 수 있다. 30종의 지침이 명암비·브랜드 적합성·재현성을 자동으로
보장하지 않는다. README의 MIT 표기 외에 별도 라이선스 파일이 확인되지 않아 자산 배포
조건을 충분히 확인했다고 주장하지 않는다.

**반영:** 독자·매체·브랜드에 따른 소수 후보, 기존 palette 토큰 유지, RGB 대비 자동 검사.
**보류:** 30종 테마 전량 복제, 새로운 전역 테마 API, 고정 해외 폰트, 장식 의무화.

### codex-ppt-skill

`skills/codex-ppt` 아래의 단계별 문서·프롬프트·상태 스크립트·이미지 제공자·조립 스크립트가
역할을 분리한다. 대표 장표 확인 후 같은 스타일로 생산하고, 작업 결과를 파일 증거로 남기는
방식과 조립 시 발표자 노트를 넣는 방식이 유용하다. `tests/test_image_gen_models.py`는
오프라인 요청 검증 테스트이며 실제 이미지 모델 품질이나 네트워크 성공을 증명하지 않는다.

장표마다 전체 이미지 한 장을 넣기 때문에 개별 텍스트·표·도형 편집이 어렵다. 화면의 숫자와
고객명이 일반 PPTX 텍스트 검사에 잡힌다고 볼 수 없다. 이미지 백엔드·API 설정·호스트
서브에이전트 가용성에 의존하는 강제 실행 계약도 공통 스킬에는 이식하기 어렵다.

**반영:** 필요할 때 대표 장표 확인, 모든 유형에 notes 보존, 사실에 근거한 발표 설명.
**보류:** 전체 이미지 PPTX 기본화, 특정 이미지 모델·API·서브에이전트의 필수화,
이미지 생성 단계마다 반복 승인하는 흐름.

### frontend-slides

고정 스테이지·뷰포트 CSS·스타일 인덱스·템플릿 팩·추출 스크립트가 연결된다. 읽는 자료와
말하는 자료의 밀도를 구분하고, 선택한 스타일만 상세 로드하며, 작은 화면에서도 비율을
유지하는 설계가 강점이다. 기존 ProposalSkills의 세 출력 프로파일에 부합한다.

`extract-pptx.py`는 상위 도형의 텍스트와 이미지를 읽지만 표 셀·차트·중첩 그룹을 재귀적으로
추출하지 않는다. 따라서 변환 결과를 원본 요구사항과 수치의 완전한 보존 증거로 쓰기 어렵다.
프런트엔드 무빌드 방식과 완전한 오프라인 실행도 다르다. HTML 템플릿에는 외부 폰트 링크가
있다. 루트와 플러그인 배포 경로에 유사 자료가 공존해 변경 시 동기화 확인이 필요하다.

**반영:** 매체별 밀도 유지, 넘치는 내용을 분할, 전체 장표와 필요한 대표 화면으로 확인.
**보류:** HTML 제출본 기본화, 추출 스크립트의 직접 도입, 빌드 불필요를 오프라인 보장으로 해석.

### guizang-ppt-skill

두 HTML 템플릿, 레이아웃·테마 참조, 발표자 런타임, Swiss·발표자·런타임 동기화 검사가 있다.
장표 목적·보충 설명·다음 장 전환과 발표 준비를 함께 계획하는 점이 유용하다. Swiss 검사는
정적 검사와 Playwright 기반 측정을 나누고, 브라우저 측정이 불가능하면 경고로 남긴다.
발표자 검사도 노트/장표 대응과 부분적인 시간 계획을 구분한다.

템플릿의 외부 폰트·CDN 아이콘과 일부 런타임 폴백은 네트워크·버전 가용성에 의존한다.
WebGL·발표자 동기화는 공공 제출용 PPTX에는 필요한 기본 기능이 아니다. AGPL-3.0 코드를
기존 공개 프로젝트에 복사하는 것은 단순한 MIT 템플릿 복제와 동일하게 취급할 수 없다.

**반영:** notes의 목적·설명·전환 계획, 미검사 상태를 유지하는 원칙, 실제 리허설 확인.
**보류:** HTML·JS·이미지·폰트 자산 복제, 발표자/관객 화면 서버 기능, WebGL 배경,
실행할 때마다 자동 상류 업데이트를 확인하는 정책.

## 3. 실제로 재현·수정한 ProposalSkills 결함

| 문제 | 수정 전 | 수정 후 | 검증 위치 |
|---|---|---|---|
| 표의 셀 수 불일치 | 추가 셀은 삭제되고 누락 셀은 공백 처리 | 열 수와 다른 행을 입력 오류로 거부 | `test_slide_quality.py` |
| 잘못된 열 폭·정렬 열 | 일부 오류가 늦게 나거나 잘못된 열을 수용 | 길이·유한 양수·열 번호 검증 | `test_slide_quality.py` |
| 발표자 노트 유실 | 본문 프레임에서만 저장 | 모든 type·분할 조견표에 보존 | `test_slide_quality.py` |
| 대비 기준이 문서에만 존재 | 색상 토큰을 쓰면 저대비 조합도 생성·검사 통과 가능 | 생성기·실물 검사에 같은 RGB 검사 사용 | `color_contrast.py`, `test_gate_integrity.py` |
| 런타임 누락 오류 계약 | 공통 검사 모듈의 전이 의존성이 기존 import 보호 밖에 놓일 수 있음 | 생성기·검사기 모두 친절한 의존성 안내와 exit 2 유지 | `test_slide_quality.py` |
| 간지 번호의 낮은 대비 | 기존 연한 색과 흰 배경 약 2.35:1 | 기존 주조색으로 교체 | 기존 3개 프로파일 및 전체 파이프라인 테스트 |

표 데이터 계약을 새로 만들거나 기존 제출 기준을 낮추지 않는다. 셀·열 폭 검증은 문서에
이미 존재하는 JSON 배열 계약을 실행 시 확인한다. 공유 대비 계산은
[W3C 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)을 참조한 독립 구현이다.
18pt 이상 또는 14pt 굵은 글자는 3:1, 그 외는 4.5:1을 사용하며 반올림 전 값을 비교한다.
템플릿 배경은 유지하고, 일반 생성 덱에는 흰 배경을 명시한다.

## 4. 새 작업 지침과 유지한 계약

`deck-production.md`와 콘텐츠 SKILL에 관계→type 선택, 소수 스타일 후보, 스토리·수치·
항목 수 대조, 목적·보충 설명·전환을 담는 노트를 연결했다. 발표자 노트는 사실에 근거하며,
분할 조견표의 노트는 생성 후 실제 페이지에 맞게 확인한다. 이미 정해진 브랜드와 요구는
다시 승인받지 않는다. 대표 장표 확인은 필요할 때 적용하며 전체 장표의 시각 검토를 대신하지 않는다.

그대로 유지하는 것은 플래그십 단일 진입점, 형제 두 스킬의 명시 호출, 발주처 규격 우선,
편집 가능한 도형·표, 원장 대조, 실제 파일 해시, 제출 묶음 확인, 렌더·사람 승인이다.
추가 외부 의존성·모델 API·새 서버·테마 엔진·고객 자료는 넣지 않았다.

## 5. 검증과 한계

수정 전 커밋을 실행한 합성 확인에서 추가 표 셀의 유실과 표지·간지·마무리의 노트 누락을
재현했다. 목차는 기존에도 노트가 저장됨을 확인했다. frontend-slides 추출기에 표 셀과
그룹 텍스트를 넣은 PPTX를 제공하면 두 텍스트가 content 목록에 포함되지 않았다.
외부 Python 파일 20개는 구문 분석을 통과했다. 이는 각 저장소의 전체 실행 테스트를 뜻하지 않는다.

회귀 검증 명령은 저장소 루트에서 `python -m unittest discover -s . -p "test_*.py" -q`이다.
새 검사에는 표의 양성/음성 대조군, 모든 유형의 노트 보존, 정상/저대비/큰 글자 RGB,
테마·투명도·패턴 배경 미검사, 실제 제출 PPTX의 저대비 차단이 포함된다.
기존 출력 프로파일·출력 규격·통합 제출 경로도 함께 재검증한다.

명암비 검사는 명시적 단색 RGB만 계산한다. 테마·투명도·이미지·부분 겹침·상속 글꼴·그룹
배경을 표시색으로 확정할 수 없으면 미검사로 기록한다. 표 셀 안의 글자 넘침, 의미적으로
맞는 단계 수·도식 결론, 폰트 대체, 전체 장표의 시각 완성도를 자동 승인하지 않는다.
외부 저장소의 실제 이미지 생성·웹 발표·관객 화면 동기화는 실행 검증하지 않았다.
전체 이력·종합 보안 감사나 특정 모델에서의 제안서 품질 점수 평가도 수행하지 않았다.

## 6. 배포와 출처

버전 1.2.1의 공통 스킬 payload를 Codex·Claude·Grok 로컬 설치 경로에 동일하게 배포한다.
설치기는 기존 폴더를 백업하고 필요한 파일만 갱신한다. ChatGPT 웹·다른 계정의 클라우드
등록은 로컬 설치와 별도이며, Grok 모델의 실제 실행 성공을 주장하지 않는다.

출처는 위 표의 고정 커밋 링크와 각 저장소의 해당 파일이다. 외부 코드·문장·템플릿·이미지·
폰트·로고를 복제하지 않았으며, 출처 표기는 외부 프로젝트의 사용·배포 조건을 대신하지 않는다.
